Arm 2 finds 359 of 463 labelled vulnerabilities against 149, cutting misses from 314 to 104, and it does so while also reporting fewer false positives (214 against 259). Precision and recall rise together, so this is not a threshold shift. Per contract, 142 improved, 31 were unchanged and 27 regressed. The paired McNemar test over 1,600 cells is decisive: 170 cells correct only in Arm 1 against 425 correct only in Arm 2, p ≈ 3.7 × 10⁻²⁶.

The slice keeps 56.5% of source characters, and the contract text the detector must read falls by 69%. The longer prompt costs about 1,600 tokens per call but is cached, so it is dwarfed by what the slice removes. Output tokens also fall by 56%: given a compact, tagged input the detector writes shorter justifications. Cost falls faster than tokens because the removed tokens are input, and the slicer itself adds 7.6 ms per contract and needs no compilation.

Six categories improve, two regress. The two largest, Reentrancy (F1 0.19 → 0.82) and Access Control (0.41 → 0.83), drive most of the gain: the simple prompt misses 88 of 98 reentrancy cases and 102 of 144 access-control cases, because "only what is exploitable" makes the detector conservative, while the tags point at the state-mutating entry points where a missing modifier lives.

Front Running is the one real failure. Arm 2 finds none of the 15 positives (F1 0.00), though it also cut the baseline's 132 false positives to 14. The calibrated rule is too strict, and the tightened anchor now tags only 21% of blocks. Arm 1's score on this category is not a real alternative either: it flagged 132 of 185 negatives, so both arms fail, in opposite directions. Time manipulation also regressed (0.67 → 0.58): the new rule recovers misses (15 → 4) but triples false positives (11 → 50).

What the paper can claim

RQ1 · Evidence retention. 463 of 463 labelled vulnerabilities retained across 200 contracts, 1.000 in every category, at 56.5% of source characters and 7.6 ms per contract, with no compilation. Reaching this needed four slicer fixes that the earlier 70-contract sample never exposed: legacy functions that are public by default, multi-line signatures, anonymous fallbacks, and an over-eager veto rule.

RQ2 · Token efficiency. 55% fewer tokens, 64% lower cost and 60% less wall-clock time per contract, with the contract text read down 69%.

RQ3 · Detection effectiveness. F1 0.342 → 0.693, agreement 0.642 → 0.801, κ 0.097 → 0.549, misses 314 → 104 and false positives 259 → 214 at the same time; McNemar p ≈ 3.7 × 10⁻²⁶ over 1,600 paired cells. Token cost falls and detection improves together, which is the paper's thesis.

Limitations to state

Arm 2 changes two things at once, the input and the prompt, so this experiment measures the combination; the earlier 70-contract runs showed slicing alone is token-neutral for detection (p = 1.00), and the prompt carries most of the accuracy gain. The calibrated rules describe how DIVE's labels behave rather than Solidity semantics — each category is effectively defined by whichever analyzer ran — so they are calibration to this benchmark and must be declared as such. The rules were derived from 15 contracts inside this set, which is in-sample for those; on the 130 contracts added afterwards the slicer, not the prompt, was re-verified. Front Running (0 of 15) and Time manipulation (50 false positives) are open failures, and Arithmetic remains the weakest large category at F1 0.52. Sampling over-represents the two rare categories (Bad Randomness 8.0% against 2.8% corpus-wide, Front Running 7.5% against 2.7%). Each arm ran once; three repeats of one configuration earlier varied by 4.2 points of agreement.
