The prompt that won on five contracts lost on fifty

A tuned prompt took Claude Opus 5 from F1 0.50 to 0.69 against DIVE's labels on a five-contract set. Rerun on fifty contracts at realistic base rates, the same prompt scores 0.43 — behind Slither, behind Solhint. One over-broad rule did nearly all the damage.

01What happened

A prompt tuned on 40 label cells did not survive 400.

The previous round tuned the system prompt against five contracts. Adding worked examples of each vulnerability moved F1 from 0.48 to 0.50; adding an explicit threshold calibration — telling the model to fire when a pattern is present rather than when an exploit is provable — moved it to 0.688, which beat every analyzer on recall. That looked like a result.

It was not. On fifty contracts drawn at close to DIVE's real base rates, the same prompt scores F1 0.427, with 91 false positives against 57 true. Slither, which was well behind on the small set, scores 0.691.

The five-contract set had 16 positive cells. Every per-category figure rested on two. That is not enough surface for a prompt change to be measured on, and the earlier round said so in its limitations — but the number still got quoted as if it meant something. This page is what the larger sample says instead.

Fifty contracts, stratified, close to dataset prevalence.

◑ Tool precision and F1 remain circular. DIVE's label is derived from these six analyzers, so they largely cannot produce a false positive against it. Recall is the column that compares honestly, because a tool can still miss a cell that a different tool put into the label.

On that column Opus scores 0.479 — level with Solhint, behind Slither's 0.563. On the five-contract set it led everything at 0.688. The lead did not survive.

Slither is the strongest predictor here on every measure, and note how much its coverage improved on this sample: it returned a verdict on 300 of 400 cells, against 14 of 40 last time. The earlier run happened to draw contracts Slither had mostly skipped, which flattered everything it was compared against.

43 of 91 false positives · one rule

Front Running: Opus flagged 46 of 50 contracts. DIVE flags 5.

The calibrated prompt included this firing rule, written after the five-contract round:

Front Running: any ERC20-style approve that sets an allowance directly, and any
public function whose payoff depends on landing before someone else.

Nearly every ERC20 token in the sample has a standard approve(). The rule fired on all of them. Of the 43 false positives, 40 give the allowance race as the reason — the model followed the instruction exactly and the instruction was wrong at scale.

The rule was not baseless: the ERC20 approve race is a real, documented hazard, and on the five-contract set it produced two clean true positives. But DIVE only labels Front Running when a tool reports it, which is rare. Writing a rule that fires on a ubiquitous pattern guarantees a false positive on every token contract in the corpus.

33 of 62 false negatives

Access Control: DIVE flags 39, Opus flags 6

The opposite failure, and the larger one in raw count. DIVE marks Access Control positive on 78% of this sample — its most common label by far, and implausibly high as a description of real vulnerability. Opus, reading source, finds it 6 times.

Mean confidence on the 33 misses is 0.54, so the model is genuinely uncertain here rather than confidently wrong. This is the category where DIVE's own labels most deserve scrutiny: at a 75% dataset-wide positive rate, the label is closer to "this contract has an owner" than to "this contract has an authorization flaw".

Reentrancy is the one clear success: 18 true positives against 5 false, F1 0.80, κ 0.64. Bad Randomness also holds up (F1 0.75) on a small base. Both are categories with crisp syntactic signatures, which is exactly where a detector and a reader agree.

05What to take from this

On the method. A prompt tuned against 40 label cells and validated on the same 40 cells is not evidence. The calibration looked like a large gain and was mostly an artifact of a tiny, category-balanced sample. The honest version of the earlier claim is: threshold instructions move the model a great deal, in whichever direction they point, and a small eval cannot tell you whether the direction generalises.

On DIVE. The audit's original finding survives, and this run strengthens it. Access Control positive on 78% of contracts and Reentrancy on 44% are not credible vulnerability rates; they are what union-of-analyzer labelling produces. The categories where an independent reader and the label agree — Reentrancy, Bad Randomness — are the ones with crisp signatures. The categories where they diverge most are the ones where DIVE's rate is least plausible.

Not shown here. Whether the calibrated prompt is worse than the plain example-augmented prompt at this scale. That arm was not run on these 50 contracts, so the comparison across prompts still rests on five contracts and should not be trusted. Running it is the obvious next step, and it is the one that would actually settle whether the calibration helped or hurt.
